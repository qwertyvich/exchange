# Casper Exchange

Ветка `palma_exchange`. Локальная версия работает с PostgreSQL 17; SQLite больше не используется для текущих заявок.

Сайт: http://localhost:5173 · API: http://localhost:8000/docs

## Запуск

На этом компьютере `.env` уже создан. Логин локального администратора находится в `ADMIN_EMAIL`, пароль — в `ADMIN_PASSWORD`. После входа откройте «Профиль → Админ → Настройки обмена».

```sh
# Обычная работа с исходниками, автоматическое обновление при правках:
docker compose up -d --build --wait

# Статическая сборка с nginx (этот вариант сейчас развёрнут локально):
docker compose -f docker-compose.prod.yml up -d --build --wait

# Остановка используемого варианта без удаления данных:
docker compose -f docker-compose.prod.yml down
```

Не запускайте оба варианта одновременно: они используют одинаковые порты и базу. Перед переключением остановите активный вариант командой `down` с соответствующим compose-файлом. Не добавляйте `-v`, если нужно сохранить базу.

Для новой установки скопируйте `.env.example` в `.env`, задайте отдельные случайные `POSTGRES_PASSWORD`, `JWT_SECRET`, `TICKET_ACTION_SECRET`, `ADMIN_PASSWORD` и свой `ADMIN_EMAIL`. На публичном сервере задайте HTTPS-адрес `PUBLIC_URL` и настройте TLS reverse proxy перед портом 5173. Существующие `nginx/default.conf` и `init-letsencrypt.sh` — старые файлы с прежним доменом, текущая Compose-конфигурация их не использует.

## Настройки и данные

После первого импорта источник настроек — PostgreSQL. Меняйте их через админку, а не через `backend/app/settings.json`: этот JSON теперь только начальный шаблон для пустой базы. То же относится к `reviews.json`.

Существующие 13 пользователей, 136 заявок и 225 отзывов перенесены. Создан дополнительный локальный администратор. Исходная SQLite сохранена в `backups/palma-before-postgres.sqlite`, вне Docker-образа и Git. Импорт защищён маркером `legacy_imported`: повторный запуск не затирает изменения. Схема меняется через Alembic, миграции выполняются перед запуском API.

PostgreSQL хранится в томе `exchange_postgres_data`, чеки — `exchange_receipt_data`. Пример резервной копии:

```sh
mkdir -p backups
docker compose -f docker-compose.prod.yml exec -T postgres pg_dump -U exchange -d exchange -Fc > backups/exchange.dump
# Восстановление выполняется отдельно в подготовленную базу:
# docker compose -f docker-compose.prod.yml exec -T postgres pg_restore -U exchange -d exchange < backups/exchange.dump
```

Резервируйте также том чеков и `.env`. Для переноса на другой сервер используйте PostgreSQL dump, а не старую SQLite.

## Курсы

В админке «Курсы» выбирается конкретное направление, например BTC → ETH. Поле ручного курса означает: **сколько клиент получает за 1 единицу отдаваемой валюты**. Это конечный курс с включённой маржой, дополнительная комиссия к нему не применяется. Обратное направление независимо.

Приоритет:

1. Ручной курс направления `direction_rates["give_id:get_id"].rate`.
2. Сохранённые тарифы: старые `course_rub`/`course_usdt` режима 2 или рублёвые диапазоны `fiat_in` режима 1.
3. Рыночное соотношение цен с общей комиссией или комиссией направления.

Старые курсы режима 2 сохраняют прежний смысл: **RUB или USDT за 1 единицу иностранной валюты**. Чтобы использовать для валюты автоматический курс, очистите соответствующий старый курс в «Реквизиты и тарифы». Для полностью ручного направления при отсутствии рыночной цены задайте также минимум/максимум в отдаваемой валюте.

Рыночные цены криптовалют: [CoinGecko simple/price](https://docs.coingecko.com/v3.0.1/reference/simple-price), резерв — [Kraken Ticker](https://docs.kraken.com/api-reference/market-data/get-ticker-information). Фиат: [официальный XML ЦБ РФ](https://www.cbr.ru/development/SXML/) с учётом номинала валюты. Курс ЦБ — ежедневный ориентир; оператор задаёт коммерческую маржу под свои фактические условия обмена. Это выбранные источники для этого проекта, а не общий источник всех обменников.

Один пакетный запрос криптовалют раз в 300 секунд на весь сайт (около 8640 за 30 дней), независимо от числа посетителей. `COINGECKO_API_KEY` позволяет подключить Demo key. Сервер соблюдает интервалы, сохраняет кэш в PostgreSQL, использует блокировку между воркерами, увеличивает задержку после ошибок. Фиат обновляется не чаще раза в час. Если криптоснимок старше 15 минут, зависимые автоматические направления закрываются; ручные направления с заданными лимитами продолжают работать. Для фиата максимальный возраст успешной загрузки — 4 дня. В ответе `/api/rates` видны источник, дата, состояние и лимиты.

`POST /api/quote` проверяет лимиты и выдаёт подписанный расчёт на 60 секунд. При создании заявки сервер берёт суммы/валюты/комиссию из расчёта; браузер не может подменить их. Повторная отправка того же расчёта возвращает существующую заявку. Денежные суммы хранятся как `NUMERIC(36,12)`, округление производится на сервере вниз: 8 знаков для криптовалюты, 2 для фиата.

## Telegram

Бот не рассчитывает и не исполняет обмен: это канал уведомлений оператору. Заявки выполняются вручную.

- `POST /api/tickets` создаёт заявку и два сообщения в чат `CHAT_ID`: суммы/клиент/реквизиты и ссылки «отменить / подтвердить» с HMAC-подписью.
- Подтверждение оплаты клиентом отправляет сообщение и, если приложен, чек. Клиентский статус становится `not_confirmed`; оператор завершает обмен ссылкой из чата.
- Форма контактов и отправка отзыва идут в `MESS_CHAT`. Отзыв не публикуется автоматически: опубликованный список отдельно хранится в базе.
- Сообщения хранятся в PostgreSQL и отправляются фоновым обработчиком. До 8 попыток с увеличением интервала. Доставка как минимум однократная: при сбое после отправки, но до записи результата возможен повтор.

**В локальном запуске `TELEGRAM_ENABLED=false`, реальные сообщения не отправлялись при проверке.** Чтобы включить отправку, задайте токен/ID чатов в админке или `TELEGRAM_BOT_TOKEN`, `TELEGRAM_TICKETS_CHAT_ID`, `TELEGRAM_MESSAGES_CHAT_ID` в `.env`, установите `TELEGRAM_ENABLED=true`, корректный `PUBLIC_URL` и пересоздайте backend. Непустые переменные окружения имеют приоритет над админкой. Ранее токен находился в Git: перед реальным включением замените его у BotFather.

## Изображения и проверка

[Карта изображений и переименования](docs/BRANDING.md) · [Результаты разбора и изменения](docs/CHANGES.md).

RU/EN переключает интерфейс без перезагрузки и сохраняет выбор в браузере. [Где редактировать переводы](docs/LOCALIZATION.md).

Переходы стеклянных панелей настроены в `frontend/src/styles/glass-motion.css`: мобильное меню появляется сверху и уходит вверх, валюты раскрываются вниз от поля и остаются привязаны к нему при прокрутке. При нехватке места уменьшается высота списка. Анимации учитывают системное уменьшение движения.

Эффекты главной находятся в `frontend/src/styles/home-motion.css`: движение фона, появление заголовка и формы, отклик кнопок и поворот стрелок. Появление запускается после полного исчезновения заставки через `homeMotionReady` в `App.vue`; сама форма при этом не смещается, чтобы список валют сохранял положение под полем.

```sh
docker compose run --rm --no-deps backend python -m unittest discover -s tests -v
cd frontend
npm ci
npx playwright install chromium
npm run test:e2e
```

Backend-тесты изолированы от рабочей базы. Браузерные тесты используют локальную админку, временно переключают режимы и восстанавливают настройки в конце; выполняйте их на локальной копии. Реальных Telegram-сообщений тесты не отправляют.
